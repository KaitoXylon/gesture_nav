One frame, step by step

  1. grab: left image + depth from the ZED
  2. odometry: VIO pose → /odom + TF
  3. people: YOLO pose track → ID, box, body center
  4. gesture: MediaPipe → STOP / FOLLOW / LOCK, after 6 frames in a row
  5. target: locked ID, or the person nearest the middle
  6. command: follow_person() → Twist on /cmd_vel
  7. print + show: terminal every 10 frames, window every frame

The code: src/gesture_nav/gesture_nav/rover_node.py

One class, RoverNode. There is no ROS timer or subscription: main() calls step() in a loop, and each call handles one camera frame.

Setup

__init__()

Reads the parameters, opens the camera, starts tracking and loads the two AI models. The controller numbers are hard-coded right at the top:

self.deadband = 0.25       # meters, do not drive if this close to the target distance
self.center_band = 0.05    # do not turn if the person is this close to the middle (0 to 1)
self.speed = 30.0          # fixed speed for forward, backward and turning
self.turn_left = -self.speed   # mt11 rover: NEGATIVE angular.z = LEFT
self.turn_right = self.speed

Main loop

main() → step()

main() turns off rclpy's own Ctrl+C handling, so the node can still send a stop command when you quit. Then it calls step() until it returns False (when you press q).

def step(self):
    if self.zed.grab() != sl.ERROR_CODE.SUCCESS:
        return True
    self.zed.retrieve_image(self.image, sl.VIEW.LEFT)
    frame = cv2.cvtColor(self.image.get_data(), cv2.COLOR_BGRA2BGR)
    self.zed.retrieve_measure(self.depth, sl.MEASURE.DEPTH)
    self.depth_data = self.depth.get_data()     # meters per pixel

    self.publish_odometry()                     # 0. odometry
    self.find_people(frame)                      # 1. people
    gesture, self.fingers = self.read_gesture(frame)   # 2. gesture
    self.update_state(gesture)

    target = self.choose_target()               # 3. speed command
    if self.state == 'FOLLOW':
        forward, turn, info = self.follow_person(frame, target)
    else:
        forward, turn, info = 0.0, 0.0, 'stopped by gesture'
    cmd = Twist(); cmd.linear.x = forward; cmd.angular.z = turn
    self.cmd_pub.publish(cmd)
    # 4. print every 10 frames, 5. show the window

People are detected on every frame, even in STOP. That keeps the tracking IDs stable, so you can lock someone at any time.

Gestures

read_gesture() · count_fingers() · is_thumbs_up()

MediaPipe gives 21 points per hand (0 = wrist, 4 = thumb tip, 8 / 12 / 16 / 20 = finger tips). Image y grows downward, so "higher" means a smaller y.

✋ Open palm4 or 5 fingers upSTOP

for tip, joint in [(8, 6), (12, 10), (16, 14), (20, 18)]:
    if points[tip].y < points[joint].y:      # tip higher than the middle joint = finger up
        count += 1

The wrist position is saved as self.hand_point (pixels). It is only used to decide who made a thumbs up. The hand never steers the rover.

4

State & lock

update_state() · lock_person() · choose_target()
if gesture is not None and gesture == self.last_gesture:
    self.same_count += 1
else:
    self.same_count = 1
# "== frames_needed" (6): fires ONCE while the hand is held
if gesture is None or self.same_count != self.frames_needed:
    return
  • FOLLOW / STOP switch the state. STOP also clears the lock.
  • LOCK does not change the state. It finds the person whose box contains the wrist and stores their YOLO tracking ID in self.locked_id. If the hand is in no box, nothing is locked.
  • choose_target(): with a lock, only that ID counts and everyone else is ignored (gray box). If the locked person is not seen, the rover stands still and waits. Without a lock, it picks the person whose body is nearest the image middle.
5

People

find_people() · body_center() · distance_at()
results = self.model.track(frame, classes=[0], conf=0.45, persist=True,
                           verbose=False, device=0, half=True)   # GPU, 16-bit
# each person: (tracking ID, [x1, y1, x2, y2], body center)
  • persist=True keeps the tracker's memory between calls, so person #1 stays #1.
  • Body center = average of shoulders (5, 6) and hips (11, 12), using only points with confidence > 0.5. A raised arm makes the box wider but does not move this point. That is why the rover no longer turns toward your hand. If no body points are found, it uses the box middle at 40% of the box height.
  • Distance = median of the ZED depth in a 15 × 15 px square around the body center (NaN and inf are dropped). These are real meters. The old box-height guess could never measure below about 2.3 m, because up close your body does not fit in the image.
6

Following

follow_person()
distance_error = distance - self.target_distance        # + = too far
# the LEFT lens is 6 cm left of the camera center: straight ahead looks a bit RIGHT
self.middle_x = self.cx + self.fx * (self.baseline / 2) / distance
side_error = (self.middle_x - body[0]) / (img_w / 2)    # + = body is LEFT

if distance_error > self.deadband:            # too far
    forward = self.speed
    if side_error > self.center_band:    turn = self.turn_left
    elif side_error < -self.center_band: turn = self.turn_right
elif distance_error < -self.deadband:         # too close: back up, no turning
    forward = -self.speed
# else: within ±0.25 m of the target, do nothing
Why the rover used to turn left when you stood in front of it. The middle was not corrected for the left lens (about 38 px off at 1.5 m), so the node asked for a small right turn. It sent the ROS sign for right (negative), and on the mt11 rover negative means left. Turning left made you look further right in the image, so it kept turning left. Tick "show the old bug" in the System tab to watch it happen.
7

Odometry (VIO)

publish_odometry()
  1. Ask the ZED for the camera pose (get_position, WORLD frame). If tracking is not OK, publish nothing.
  2. Move from the camera to the rover center: base = camera_position − R · [camera_x, 0, camera_z].
  3. Heading: yaw = atan2(R[1][0], R[0][0]).
  4. Speed from the change since last frame: forward = movement along the heading ÷ dt, turn rate = change in yaw ÷ dt (wrapped to ±π).
  5. Publish /odom (frame odom → base_link) and the same transform on TF.

Odometry uses the ROS sign convention (+yaw = left). Only the mt11 motor command on /cmd_vel is flipped.

  • Printed every 10 frames; gesture events print right away (>>> Locked person #1 …).
  • The window shows the hand, the boxes (green = followed, gray = ignored), the body-center dots, the corrected "straight ahead" line, the state, the command and the odometry.
  • On q or Ctrl+C: send a zero Twist, stop tracking, close the camera and MediaPipe. Further Ctrl+C presses are ignored so this can finish.
